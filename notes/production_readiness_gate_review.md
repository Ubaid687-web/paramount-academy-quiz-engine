# Paramount Academy Quiz Engine — Production-Readiness Gate Review

**Decision:** **No-go for a broader teacher rollout.** The platform is suitable only for a tightly controlled owner-admin pilot until the P0 issues below are resolved. Do not add dashboards, analytics, manual retries, or new assessment modes before this gate is cleared.

The previous architecture audit correctly identified the intended product direction, but it was not sufficiently evidence-based. It describes target principles; it does not demonstrate that the current system is operationally ready. Several claims must be corrected before we proceed.

| Priority | Verified gap | Evidence | Why this is blocking | Required decision / corrective action |

## Corrections to the Previous Architecture Audit

The following statements are **directionally correct but not currently proven** and must no longer be presented as completed production capabilities:

1. **“Admin generation history and monitoring queries now capture retry counts.”** This is false today. The count is stored only for successful MCQ calls and is not exposed as an admin history surface.
2. **“Teacher roles are locked down.”** This is false today. The implementation has only `user` and `admin`, and generation currently requires `admin`.
3. **“Deployment hardening” is a future phase, not a minor final task.** Schema migration drift and generation-capacity availability make it an immediate release blocker.
4. **“Zero-tolerance duplication” is an important guardrail, not a mathematical guarantee.** It is a model-output validation policy. It still needs sampled academic review across each active subject.

## Mandatory Sequence Before New Features

1. **Repair release integrity:** create the missing schema migration and test a clean migration replay.
2. **Repair access control:** introduce teacher/admin responsibilities without granting curriculum-management power to teachers.
3. **Repair Chemistry source integrity:** clear or isolate all unresolved OCR pages.
4. **Establish generation availability:** resolve the deployed account’s capacity problem and complete real smoke tests.
5. **Add structured question traceability and human review gates.**
6. **Only then** conduct the three-subject end-to-end acceptance pack and decide whether the teacher pilot can expand.

## Explicit Deprioritization

Do **not** build an admin analytics dashboard, retry-rate alerts, automatic retries beyond the existing bounded transport policy, student-facing sharing, spaced repetition, new subjects, or expanded assessment formats until the P0 blockers are closed. Each would increase surface area while the core trust chain—source quality, correct roles, reproducible releases, and reliable generation—remains incomplete.

> **Production standard:** A teacher must be able to select approved material, create a source-cited draft, review it, print it, and explain where each answer came from—repeatedly, with predictable access and service availability. Until that is demonstrated for every active subject, the platform is an advanced pilot, not a finished academy product.
